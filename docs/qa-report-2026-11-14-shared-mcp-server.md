## 실측이 바꾼 설계

처음 판의 신원 규칙으로 이 Mac 에 열려 있던 세션 20개를 넣어 보니 공용 서버가 7개로 갈렸다. 가른 것은 세션마다 다른 LLM 관련 환경값이었고 서버 코드는 그 값을 읽지 않는다. 그래서 LLM 설정과 로캘을 서버 신원에서 빼고 접속이 선언하게 바꿨다. 같은 세션들이 새 규칙으로는 2개다(`.qa-artifacts/v1.9.0/level3/census/` — 값은 기록하지 않고 이름·조합 수·크기만).

## 측정 도구에서 고친 것

- 레벨2 H-004 가 한 번 실패했다(조용할 때 주입 0건). 프로브가 훅 세션 번호를 실행마다 같게 썼고, 실데이터 사본에 앞선 실행의 세션별 주입 장부가 남아 전부 "이미 주입함"으로 걸러졌다. 세션 번호에 실행 표식을 붙여 다시 재니 12/12 였다. 제품의 세션별 중복 제거는 설계대로였다.
- 레벨4 의 첫 스냅샷은 중계 19개를 "옛 전체 서버"로 분류했다. 도구가 `ps` 의 시작 시각을 한국어 로캘 표기로 받아 읽지 못했고, 읽지 못한 것을 옛 코드로 쳤다. C 로캘로 읽고, 읽지 못하면 "모름"으로 따로 세게 고쳤다. 메모리 합계와 서버 수는 이 결함과 무관하다.
- 레벨4 의 첫 범위 확인은 무효였다. 새 설치 폴더의 첫 실행이 의존성을 설치하는 동안 로컬 플러그인 서버가 아직 연결 전이었고, 확인용 세션이 이름이 비슷한 다른 서버의 도구를 불렀다. 도구 이름을 정확히 지정해 다시 실행했다(`level4/scope-checks-first-wrong-tool.json` 에 첫 결과).

## 남은 한계·잔여 목록

- 프롬프트 주입 데몬의 소켓은 (색인 폴더, 버전)마다 하나다. 서버 설정이 달라 공용 서버가 여럿이면 그중 하나가 모든 세션의 훅에 답한다 — 1.8.0 과 같은 동작이다. 프로젝트 범위는 섞이지 않지만(주입 범위는 요청이 싣는 작업 폴더), 세션마다 DB 경로·임베딩 모델을 다르게 준 경우 훅은 소켓을 쥔 서버의 값으로 계산된다. 이 Mac 의 실제 세션에서 서버를 가른 값은 주입 계산이 읽지 않는 값이어서 판정이 달라지는 경우는 없었다. 고치려면 훅 클라이언트의 프로토콜을 바꿔야 한다(계획 Open Questions). 서버는 자기가 그 소켓을 쥐고 있는지 로그에 남긴다.
- 살아 있는 무관한 프로세스의 pid 가 적힌 기동 잠금 파일이 있으면 첫 연결이 46초까지 늦는다. Claude Code 의 MCP 기동 대기 기본값(30초)을 넘으므로 그 세션의 첫 연결은 실패할 수 있다. 다음 연결은 바로 붙는다.
- 세션별 방식(1.8.0 과 같은 구조)으로 도는 경우가 여섯 가지 있다: 끄기 스위치(`MEMORY_BANK_SHARED_SERVER=0`) · 끄기 파일(`conversation-index/shared-server.off`) · Windows · 소스에서 직접 실행 · 설정 폴더 경로가 유닉스 소켓 한도를 넘는 경우 · 세션이 작업 폴더를 모르는데 경로 설정이 상대 경로인 경우. 각각 stderr 에 사유를 한 줄 적고, 이 밖의 이유로는 세션별 방식이 되지 않는다(설치가 깨진 경우는 실패로 끝난다).
- `MEMORY_BANK_` 로 시작하는 환경 변수는 전부 서버 설정으로 본다 — 세션마다 다르게 주면 서버가 갈린다.
- 소켓·잠금·pid 파일은 소유자 전용이지만, 같은 사용자 계정으로 도는 다른 프로세스까지 막지는 않는다.
- 넘기지 못한 LLM 설정이 256개를 넘는 세션의 접속은 거절된다(실측 최대 26개).
- 공용 서버의 메모리는 쓰는 만큼 는다(임베딩 모델을 올리면 약 0.8GB — `level2/r4/probes-b.json` H-008). 위 1,532MB 는 설치 10분 뒤 값이다.
- 구조: `runRelay`(270줄)·`startSharedServer`(212줄)가 길다 — 계획 Open Questions.
